# Заявки з сайту → Telegram-група

Форми сайту (зворотний зв'язок і підписка) надсилають дані на Cloudflare Worker, а він пересилає їх у Telegram-групу від імені бота. Токен бота зберігається лише в Cloudflare і ніколи не потрапляє в код сайту.

## 1. Дізнатися CHAT_ID групи

1. Напишіть будь-яке повідомлення в групу (бот уже має бути в ній).
2. Відкрийте в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, підставивши токен бота.
3. Знайдіть `"chat":{"id":-100...` — це і є CHAT_ID (від'ємне число, разом з мінусом). Якщо там порожньо — напишіть у групу ще раз і оновіть сторінку.

Якщо id змінювався (група стала супергрупою), беріть останній, що починається з `-100`.

## 2. Створити Worker

1. Зареєструйтесь на [dash.cloudflare.com](https://dash.cloudflare.com) (безкоштовно).
2. **Workers & Pages → Create → Create Worker** (шаблон "Hello World"), назвіть `fsf-leads`, натисніть **Deploy**.
3. **Edit code** → видаліть усе й вставте вміст `worker.js` з цієї папки → **Deploy**.
4. **Settings → Variables and Secrets → Add**, тип **Secret**:
   - `BOT_TOKEN` — токен бота від @BotFather
   - `CHAT_ID` — id групи з кроку 1
5. Скопіюйте адресу воркера, вигляду `https://fsf-leads.<ваш-субдомен>.workers.dev`.

## 3. Підключити сайт

У `assets/js/app.js` замініть значення `LEADS_ENDPOINT` на адресу воркера з кроку 2 і закомітьте зміни — GitHub Pages оновиться за хвилину-дві.

## Перевірка

Надішліть тестову заявку на сайті — в групі має з'явитися повідомлення. Якщо сайт показує помилку надсилання, подивіться логи воркера в Cloudflare (**Observability / Logs**): там буде відповідь Telegram (найчастіше — неправильний CHAT_ID або токен).

Якщо сайт переїде на інший домен, додайте його в масив `ALLOWED_ORIGINS` у `worker.js` — запити з інших адрес воркер відхиляє.
