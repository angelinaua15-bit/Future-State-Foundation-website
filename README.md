# Фундація майбутнього держави — сайт (HTML/CSS/JS)

Односторінковий адаптивний сайт на **чистому HTML, CSS та JavaScript — без збірки, без фреймворків, без npm**. Відкривається напряму в браузері і публікується на GitHub Pages без жодних build-кроків.

## Як подивитись локально

Просто відкрийте `index.html` подвійним кліком у браузері — сайт повністю самодостатній.

Якщо браузер блокує `fetch`/шрифти при відкритті файлу напряму (рідко буває через локальні CORS-обмеження), запустіть будь-який простий локальний сервер:

```bash
python3 -m http.server 8080
# або
npx serve .
```

і відкрийте `http://localhost:8080`.

## Як викласти на GitHub

1. Створіть новий репозиторій на GitHub (Public, без README/gitignore — вони вже є тут).
2. У цій папці:
   ```bash
   git init
   git add .
   git commit -m "Init: сайт фундації"
   git branch -M main
   git remote add origin https://github.com/<ваш-акаунт>/<назва-репо>.git
   git push -u origin main
   ```
3. Щоб отримати живе посилання — **GitHub Pages**:
   - Settings → Pages → Source: **Deploy from a branch** → Branch: `main`, папка `/ (root)` → Save.
   - Через 1–2 хвилини сайт буде доступний на `https://<ваш-акаунт>.github.io/<назва-репо>/`.

Ніякого build-кроку тут немає, тому не буде повторення історії з v0/Vercel — GitHub Pages просто роздає файли як є.

## Структура проєкту

```
index.html               — уся розмітка сторінки, 10 секцій за ТЗ
assets/
  css/style.css           — усі стилі й анімації (дизайн-токени у :root)
  js/i18n.js               — словник текстів інтерфейсу UA/EN
  js/data.js                — контент: команда, новини, контакти
  js/app.js                  — вся логіка: рендер, i18n-перемикач, конструктор участі,
                                карусель новин, лічильники, форми, модалка команди
  img/                       — логотип (кілька розмірів + favicon), фото команди, зображення-заглушки
```

Ніякого бандлера немає навмисно: `app.js` рендерить контент із `data.js`/`i18n.js` у DOM при завантаженні сторінки і при перемиканні мови — досить відкрити код у будь-якому редакторі, усе видно одразу.

## Що реалізовано

- **Структура сторінки**: Header → Hero (з чесними фактами про фундацію) → Про нас (місія за статутом + блок «Як ми влаштовані» з органами управління) → Напрями (8 карток за реальними напрямами статуту, зокрема підтримка ветеранів/військових та ВПО) → Команда (4 картки + модалка з біографією) → Конструктор участі (3 кроки → персональна рекомендація напряму) → Медіа/Новини (карусель із навігацією prev/next та індикаторами-крапками, touch-свайп через scroll-snap) → Контакти → Footer.
  Секції «Проєкти», «Результати» (лічильники фейкових досягнень) та «Партнери» **навмисно прибрані** — фундація щойно заснована (18.08.2026) і ще не має ні реалізованих проєктів, ні підтверджених партнерів, тож на сайті лише перевірювані факти. Коли з'являться перші реальні кейси й партнери — ці секції можна додати назад за тим самим патерном, що й Команда/Медіа.
  Весь текст про місію, напрями діяльності та структуру управління взято безпосередньо зі статуту організації (розділи 3 і 5) — нічого не вигадано.
- **UA/EN** — перемикач у хедері (desktop і mobile), запам'ятовує вибір у `localStorage`, увесь текст продубльовано в `assets/js/i18n.js`.
- **Кольори бренду**: Blue `#00469B`, Yellow `#FEC301`, Dark Blue `#01226B` — визначені як CSS-змінні у `:root` (`assets/css/style.css`).
- **Анімації**: поява блоків при скролі (IntersectionObserver + CSS transitions), анімовані лічильники цифр, намальована лінія «коренів дерева» в Hero (echo логотипу), градієнт, що слідує за курсором у Hero, плавні переходи кроків конструктора, hover-ефекти на картках/кнопках. Фон кожної секції — не суцільний білий: крапковий візерунок + діагональний кольоровий градієнт, що повільно «дихає» (зміщення `background-position`), плюс три плаваючі розмиті кольорові плями (жовта/синя/темно-синя), кожна зі своєю траєкторією й ледь помітним зсувом відтінку (`hue-rotate`); непарні й парні секції дзеркалять розташування плям, щоб сусідні блоки не виглядали однаково. Усе вимикається автоматично при `prefers-reduced-motion: reduce`.
- **Доступність (WCAG)**: skip-link, семантичні `header/main/footer/nav`, видимий фокус (`:focus-visible`), клавіатурна керованість (мобільне меню, модалка команди закривається по Esc і повертає фокус), `fieldset`-подібна група радіо-кнопок у конструкторі участі, `aria-live` на статусах форм, контрастні кольори.
- **Форми**: валідація на чистому JS (ім'я, email, повідомлення, згода на обробку даних) з видимими повідомленнями про помилки, honeypot-поле проти найпростіших ботів.
- **SEO**: `<title>`, `meta description`, Open Graph теги, семантична розмітка.
- **Оптимізовані зображення**: логотип оброблено в кілька розмірів (16/32/180/192/256/512 px) + favicon; усі декоративні зображення — легкі SVG.

## Підключення форм до реального відправлення

Зараз форма зворотного зв'язку та підписка на розсилку працюють **повністю на фронтенді** — після валідації показують повідомлення про успіх, але нікуди дані не надсилають (у статичному GitHub Pages немає сервера за замовчуванням). Щоб підключити реальну відправку, найпростіші варіанти без бекенду:

1. **Formspree** (найшвидше): зареєструйтесь на [formspree.io](https://formspree.io), отримайте endpoint виду `https://formspree.io/f/xxxxxxx`, і в `assets/js/app.js` у функції `bindContactForm()` замініть блок `setTimeout(...)` на реальний `fetch(endpoint, { method: "POST", body: new FormData(form) })`.
2. **EmailJS** — аналогічно, без сервера, лист летить напряму з браузера через їхній SDK.
3. **Власний бекенд** — якщо з'явиться хостинг з підтримкою серверної частини (Node/PHP/тощо), замінити `fetch` на свій API endpoint.

Те саме стосується форми підписки на новини (`bindNewsletterForm()` у `app.js`) — під'єднайте Mailchimp/Brevo forms API аналогічно.

## Контент, який потрібно замінити

1. **Команда** — фото та біографії заповнено для всіх 4 показаних учасників (Ростислав Зайченко, Катерина Космацька, Дмитро Івченко, Максим Геймур — усі підтверджені керівні особи за статутом і протоколом №1). Щоб додати ще когось із команди, впишіть новий об'єкт у масив `team` у `assets/js/data.js` і покладіть фото в `assets/img/team/`.
2. **Партнери** — секцію прибрано, бо підтверджених партнерів поки немає. Коли з'являться — найпростіше повернути попередній блок (marquee-стрічка логотипів) за тим самим патерном, що й Команда: масив у `data.js` + рендер-функція в `app.js` + секція в `index.html`.
3. **Новини** — стрічка-карусель унизу секції «Медіа» наповнена оригінальними текстами за мотивами офіційного Telegram-каналу фундації (`assets/js/data.js → news`). Коли з'являться нові пости — додавайте нові об'єкти в цей масив, карусель підхопить їх автоматично.
4. **Проєкти й результати** — секції прибрано, бо фундація ще не має завершених проєктів чи виміряних результатів. Коли з'являться перші реальні кейси з конкретними цифрами — їх варто додати як окрему секцію з чесними даними (а не поверненням старих фейкових метрик).
5. **Юридичні реквізити** — повна назва, адреса та дата заснування вже заповнені в `i18n.js → contact.legalName / legalAddress` (на основі статуту й протоколу №1 від 18.08.2026). Код ЄДРПОУ додайте в `contact.legalEdrpou`, коли організацію буде зареєстровано.
6. **Контакти** — email/телефон у `data.js → contact` (поки заглушка — додайте реальні), посилання на соцмережі в `data.js → social` вже реальні (Facebook, Instagram, Telegram).

## Технічні вимоги — статус

- Адаптивність (mobile/tablet/desktop) — так, mobile-first, перевірено без горизонтального скролу.
- Доступність (WCAG, керованість з клавіатури) — так, див. вище.
- Валідація форм — так, на чистому JS, з honeypot проти ботів.
- Оптимізовані зображення — так (SVG-заглушки легкі; логотип у кількох розмірах).
- Проста CMS — у цій версії контент лежить у читабельних JS-файлах (`data.js`, `i18n.js`), редагування не потребує знання HTML/CSS, лише текстового редактора. Повноцінна візуальна CMS (наприклад, headless-рішення) — окремий наступний крок, якщо буде потрібен.
